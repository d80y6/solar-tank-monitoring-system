1. System Flow Summary

FTM is used to manage and monitor fuel levels in tanks across several locations/STOs. A device reads the sensor, sends data to the server endpoint, then the dashboard displays volume, fill percentage, remaining runtime, device status, charts, and location.

Big flow: User registers -> admin approves the account -> user requests a device -> admin reviews the device -> the system creates the firmware/device key -> firmware is uploaded to the device -> the device sends data -> the dashboard shows monitoring.
Area Main function Roles that usually use it
/register Request a new account. New users/operators/technicians
/login Sign in to the system once the account is active. All active users
/dashboard Compact monitoring of all STOs. Users and admins
/dashboard/devices/request Request a new device/STO. Users and admins
/dashboard/admin/users Review user accounts, roles, status, and sessions. Admin
/dashboard/admin/device-requests Review device requests and firmware packages. Admin

2. User Access Rights

User / Operator

  • Request an account and sign in once approved.
  • Request a new device/STO.
  • View the monitoring dashboard and operational details.
  • Download reading CSV from the operational detail page.
  • Contact the admin through the helpdesk live chat.

Admin / Developer

  • Approve or reject new accounts.
  • Change account role/status and revoke user sessions.
  • Approve or reject device requests.
  • Resend or regenerate firmware packages.
  • Reset readings, delete monitoring data, and check the audit log.
Security note: admin access is only granted to truly trusted accounts. Admin actions such as resetting readings and deleting monitoring data directly affect operational data.

3. New User Registration

Registration is used to request dashboard access. The account is not active immediately; the email must be verified and the admin must approve the request.

Open the registration page

Open /register, then fill in the access request form.

Fill in the main identity

Enter full name, username, work email, phone number, and job role. The phone number is stored in a consistent Indonesian format.

Create a password

Fill in a password of at least 10 characters and repeat it in the password confirmation field.

Fill in the access note

Explain the reason for access, for example needing to monitor the tank status of a particular area STO. This note helps the admin assess the request.

Complete the security check and send

If captcha is active, complete the security verification. Press Request access.

Check the verification email

Once the request is accepted, check your work email and click the verification link. The admin still needs to approve the account before it can be used to sign in.

Field Description
Full name User name matching work identity.
Username Username for account identification.
Work email Email used for verification and admin communication.
Phone number Indonesian mobile number, e.g. 08xx or +628xx.
Job role Monitoring operator, field technician, or operational reviewer.
Access note The reason or scope of access being requested.
When registration succeeds, a notification can arrive in the Telegram topic New Account so the admin immediately knows an account request arrived.

4. Admin Account Approval

The admin reviews new accounts from the /dashboard/admin/users page. Unapproved requests appear in the pending access requests section.

Sign in as admin

Sign in to the system with an active admin account.

Open User Management

Choose the User Management menu in the dashboard header.

Check the request data

Check name, email, username, requested role, email verification status, and access note.

Make a decision

Press Approve if the data is valid. Press Reject if the data does not match. If the email has not been verified, the admin can choose Send verification.

Manage active accounts

In the user list, the admin can change the role, deactivate an account, reactivate an account, revoke sessions, or send a password reset.

6. New Device Request

Device requests are made from /dashboard/devices/request. The user fills in location data, tank configuration, sensor, and generator load. The system automatically calculates tank capacity and diesel consumption.

The device is not active after the form is sent. The admin must review and approve it so the system creates the device key and firmware package.

6.1 STO Location Data

Field Description Example
STO name The location name that will appear on the dashboard. STO Bangil
Regional / Territory / Area The location group order from the largest to the closest to the STO. TREG 5 / TIF 3 / Pasuruan
Latitude Optional, supports up to 7 decimal places. -7.7201234
Longitude Optional, supports up to 7 decimal places. 112.8801234

6.2 Sensor and Tank

Choose the tank shape

Choose Rectangular tank for a box tank, or Horizontal cylinder tank for a sleeping tube.

Choose the sensor mode

The currently active mode is Fuel sensor. The energy mode is not yet active for operations.

Choose the hardware profile

The hardware profile determines the board, sensor, trigger pin, and echo pin used by the firmware.

Fill in tank dimensions

For a box tank, fill in length, width, and height. For a horizontal cylinder, fill in length and diameter.

Fill in the sensor reference

The sensor reference is the height/distance of the sensor installation used as the field reading reference. This value differs from the physical tank height if the sensor is not exactly at the top tank boundary.

6.3 Automatic Tank Capacity

The user does not need to fill in capacity in liters manually. The system calculates it from the dimensions:

Rectangular tank: capacity_liters = length_cm x width_cm x height_cm / 1000 Horizontal cylinder tank: capacity_liters = 3.14159 x (diameter_cm / 2)^2 x length_cm / 1000

6.4 Generator Load and Diesel Consumption

The system calculates consumption in liters per hour from the location load, load unit, diesel engine capacity, and cos phi.

Field Description
Location load The load value currently in use at the location.
Load unit Choose kW or kVA depending on the available data.
Diesel engine capacity Fill in the generator capacity in kVA.
Cos phi The power factor value, commonly 0.8. Fill between 0 and 1.
Short formula: kw_max = capacity_kva x cos_phi load_percent = load_kw / kw_max consumption_liters_per_hour = capacity_kva x load_percent x 0.21 If the load is entered as kVA: load_kw = load_kva x cos_phi

6.5 Send the Request

Make sure the preview makes sense

Check the automatic liter capacity and diesel consumption. If they look unreasonable, re-check the dimensions, load unit, and cos phi.

Press Request device

The system creates a request code and stores the request status. A notification arrives in the Telegram topic New Device.

Monitor request history

The history section shows status, request code, STO, device, capacity, consumption, and notes if the request was rejected.

7. Admin Device Review and Activation

The admin reviews device requests from /dashboard/admin/device-requests. This page shows the request list and a detail modal.

Open the Review requests page

Sign in as admin, then open the Review requests menu.

Choose a request item

Press Review on the request to check. The admin can view location, tank specifications, operational data, hardware profile, and validation notes.

Validate field data

Make sure coordinates, tank dimensions, sensor height/reference, sensor mode, hardware profile, and diesel consumption are correct.

Approve or reject

Press Approve if the data is valid. Press Reject and fill in the reason if the data needs fixing.

Manage the firmware package

After approval, the admin can resend the package link, regenerate the package, revoke provisioning access, or delete the request data if truly needed.

Status Meaning
Waiting for admin A new request arrived and has not been reviewed.
Approved, waiting for firmware package The admin approved it; the system is preparing the package.
Firmware package ready The firmware/device package is ready to download or resend.
Waiting for firmware download The user/technician has not downloaded the firmware package.
Waiting for device online Firmware is ready; the system awaits the first valid ping/data.
Device active The device has sent valid data and appears in monitoring.
Rejected / Revoked / Expired The request is inactive or needs to be recreated.

8. Uploading Firmware to the Device

After the admin approves the request, the system prepares a firmware package containing the device configuration. The firmware file can be used by a technician to upload it to the board matching the hardware profile.

Download the firmware package

Open the package link from the email or admin page, then download the firmware file provided by the system.

Open the firmware in Arduino IDE

If the generated result is text/script, copy the script contents into a .ino file in Arduino IDE. Make sure the board, port, and libraries match.

Check the important configuration

Check Wi-Fi, API URL, device id, API key, provisioning key, tank dimensions, coordinates, trigger pin, and echo pin.

Upload to the board

Connect the board, select the port, upload the firmware, then open the Serial Monitor to confirm the sensor reads data and the POST succeeds.

Validate the first data

If the POST succeeds, wait for the dashboard to refresh. The device moves to active status once the server receives valid data.

Do not share device keys, tokens, Wi-Fi passwords, or database URLs with unauthorized parties. Secret data may only live in secure configuration files.

9.1 Main Dashboard

The main dashboard shows a summary of all STOs. Use this page to see conditions quickly and determine which locations need checking.

Feature How to use

Search STOs Search by code, name, regional, territory, area, or device.

Check quick status

Make sure the Online/Offline badge and last update time match the device send interval.

9.2 Tank Operational Detail

The operational detail page can be accessed by active users. This page is used to monitor the daily condition of one STO.

Data resolution: the latest values on the dashboard update roughly every 20 seconds. To preserve storage capacity, long-term history is rolled up every 5 minutes with sample count, mean, minimum, and maximum values.
Section Information displayed
Tank content Current volume versus maximum capacity.
3D visual Box or cylinder tank model with the fuel level.
Device status Online, delayed, offline, or unknown.
Remaining hours/runtime Estimated operation duration based on volume and L/hr consumption.
Volume trend Chart of volume changes from the weighted 5-minute summary and daily/weekly/monthly range options.
Download CSV Download bucket times, sample counts, means, minimums, and maximums for analysis or reports.
Tank dimensions Length, width/diameter, capacity, and hourly consumption.
Operational information Regional, territory, area, device code, tank type, capacity, and reading time.

9.3 Runtime Parameters

Category Range Operational meaning
Critical < 13 hrs Priority for fast action.
Threshold Under 13 - <14 hrs Approaching the lower limit.
Under 14 - <16 hrs Below the ideal operational zone.
Threshold Upper 16 - <19 hrs Starting to enter the safe zone.
Upper 19 - <24 hrs Normal upper zone.
Overstock >= 24 hrs Very long runtime reserve.

9.4 Admin Technical Detail

The admin can open technical analysis for deeper information: empty space height (sensor distance to the fuel surface), fuel height, capacity, sensor height, dimensions, consumption, low level, critical level, RSSI, battery, received time, configuration review, raw payload, location, and the sensor data flow.

10. Operational Admin Features

Reset readings per STO

On the dashboard card, the admin can choose the reset readings button to clear the history and latest snapshot of one STO. STO data, tank, device, requests, and firmware remain.

Reset all readings

The admin can clear all reading history and snapshots so the dashboard starts reading fresh data. This action requires a confirmation phrase.

Delete STO monitoring data

Deletes reading data, devices, tanks, and events for a particular STO. Accounts, admins, firmware templates, and hardware profiles stay safe.

MySQL backup

Run a database backup per the operational SOP before major changes or before mass data cleanup.

Reset and delete actions must be performed after operational approval. Use these features for correcting test data or data that is truly no longer relevant. FTM shows a confirmation modal explaining the target and impact before a sensitive action runs.

12. Quick Troubleshooting

Symptom Common cause Check steps
User cannot sign in Account not active, email not verified, or wrong password. Check status in User Management, resend verification if needed.
Device request not appearing in monitoring Not yet approved by admin or the device has not sent valid data. Check request status, firmware package, and device Serial Monitor.
Dashboard unchanged after device POST Device ID/API key mismatch, data rejected, or dashboard not refreshed. Check the POST response, server logs, the /api/ingest endpoint, then refresh the dashboard.
Offline status Last data is beyond the expected send interval. Check Wi-Fi, device power, send interval, and connection to the server.
Volume or runtime looks unreasonable Tank dimensions, sensor reference, or L/hr consumption are wrong. Compare the configuration with the physical tank size and generator parameters.
Map marker is inaccurate Latitude/longitude entered incorrectly. Use coordinates with precision up to 7 decimal places.
Telegram not receiving notifications Bot token, group chat ID, topic thread ID, or webhook not correct. Check environment configuration and make sure the bot is a group admin.

Operational Checklist

Before users use the system

  • The account is approved by the admin.
  • The user email is verified.
  • The user role matches the need.
  • The user can sign in to the dashboard.

Before device installation

  • Tank dimensions are re-measured.
  • The sensor reference matches the installation position.
  • Location coordinates are correct.
  • Generator load, kVA capacity, and cos phi are valid.

During firmware testing

  • The sensor reads a valid distance.
  • The Serial Monitor shows a successful POST.
  • Device ID and API key match the database.
  • The dashboard receives new data after refresh.

While monitoring runs

  • Device status is online.
  • Volume and percent make sense.
  • Runtime matches L/hr consumption.
  • Charts and reading CSV are available.
